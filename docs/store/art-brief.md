# 膠囊圖與主視覺｜美術外包需求

## 委託目標

讓縮圖一眼讀出「水下機器人、觀測工作、纜線牽引」，並以燈光照出的目標引導視線。情緒是專注、好奇與水下作業的張力。不要把作品畫成武裝潛艇、太空飛船、恐怖生存或水下城市建造遊戲。

**本次只規劃，不製作最終美術。** 名稱尚未定稿，字標先留獨立圖層；商標檢索與原創載具造型核准後才定稿。所有真實廠商名稱、機型商標、標誌、可辨識外觀與識別配色都禁止；不能用去標誌、改色或鏡像來規避。內訓版舊模型不是 Steam 美術參考來源。

## 主視覺構圖方向

交兩個草圖方向供選擇，均以同一原創載具設計為基礎：

1. **近距觀測**：載具位於畫面右下，前方燈光照亮左側結構／礁岩的一小片細節；纜線向右上畫外延伸，暗示與水面的連結。背景逐層衰減，字標放左上較安靜的水色區。
2. **沿纜下潛**：垂直版本採上方水面微光、中央原創載具、下方觀測目標；纜線以緩曲線連接深度層次，保留字標的清楚負空間。縮成小膠囊時去掉細碎背景，保住字標與燈光形狀。

使用冷藍綠水體、近物中性色與少量暖色照明對比；顏色服務光路與視覺焦點，不仿現有機型塗裝。纜線要連到可信的接點，推進器／燈／鏡頭應符合已核准遊戲模型。看得出纜線與水阻的存在，但不要畫成電光武器或僵直鎖鏈。

以可玩的港灣、礁區、原創沉船外側為素材語彙，不畫未承諾的艙內穿越、巨型海怪、爆破、載人艙或軍事戰鬥。主視覺可以是原創插畫，但應對得上發行版模型與內容；另標明它是 key art，絕不混入商店截圖欄。

## 必須避免的元素

- 任何現實廠商、載具機型、第三方商標／字標、可辨識輪廓、特徵配置、專屬塗裝，以及真實遙控器／App 介面的複製。
- 非自有或未授權的照片、船名、港口識別、人物肖像、來源不明的素材與字體。不得照描內部研究圖或競品美術。
- 膠囊中的售價、折扣、評分、評論引句、得獎標章、平台標誌、願望清單呼籲、更新宣傳或其他非遊戲標題文字。依 [Graphical Asset Rules](https://partner.steamgames.com/doc/store/assets/rules) 做最終複核。
- 以文字／圖徽暗示手把全面支援、平台認證、教育認證、真機授權或尚未完成的多人功能。
- 堆滿 HUD、工程表格與小按鈕；黑到縮圖辨識不出主體；濁水被畫成無限透明；用巨大空白海域掩蓋內容。

## 外包交付與驗收

先交灰階構圖草稿與原創外形對照，再交色稿，最後套各尺寸。母版建議至少 6000×4000、分層 sRGB（這是製作建議，非 Steam 規定），能向左右與上下延展；主體、水體、近景、粒子、光束、纜線、字標分層，不能只交一張合成 JPG。另交可編輯字標向量、保留文字版與轉外框版、透明 PNG、無字母版及上述各尺寸成品 PNG。繁中、簡中、英文標題各輸出一組（定名後），不在一張小膠囊塞三種語言。

檔名建議 `capsule_header_en_920x430.png`、`capsule_small_zh-Hant_462x174.png`、`library_hero_3840x1240.png`；附色彩設定與尺寸清單。檔案交付到專案指定素材空間，不在本文件 PR 提交大型母檔。

交授權清單：來源、作者、下載連結、授權全文與修改內容。新增第三方資產遵守倉庫允許的 MIT／BSD／Apache／zlib／CC0 範圍，尤其紋理優先 CC0；不符合者先更換，不能默認可商用即合格。原創委託合約需明確允許全球商業發行、裁切、改作、三語字標與後續宣傳，提供可編輯來源並確認無侵權素材。此規劃不新增依賴或資產，實際導入時再依倉庫規範記錄授權。

驗收時逐張核對像素、sRGB、透明度、裁切與縮圖可讀性；用 Steam 官方模板檢查所有顯示區，特別是 Library Hero 視差和 Small Capsule 的 120×45 版本。最終品牌審查需同時看輪廓、配置、塗裝與文字，不只搜尋名稱。與 HUD／水下畫質／場景建模負責人共同對照候選發行版，確保美術沒有承諾不存在的玩法。
