# R4：劇情、設定、世界觀補強（Codex，只寫文件與台詞資料）

> 先完整讀 `docs/prompts/R0-common.md`。分支 `task/R4-story-world`。**最先跑**：R1–R3 會讀你的成果。

## 背景

擁有者：「劇情啊、設計啊、設定啊，都缺點意思。」現有 `docs/story/bible.md` 有角色與無線電規範，
但缺：玩家為什麼在乎、角色之間的關係與變化、貫穿各章的線索、世界的細節。開場是倒敘（風場導管架 C 腿纜線勾纏），
目前沒有任何章節回收這個伏筆。

## 要做的事（全部寫在 `docs/story/`）

1. `docs/story/bible.md` 增補（保留既有內容與審查註記；小艇取代 24 m 工作船）：
   - **主線問題**：一句話說清楚玩家這一季要證明什麼、會失去什麼（例如見習駕駛員能不能在季末前拿到正式執照，
     接下公司第一個風場合約）。
   - **角色弧線**：林岑、周楷、方晴、馬力各一條小弧線，每章推進一步；角色之間至少兩組有張力的關係。
   - **伏筆與回收**：開場的 C 腿事故是季末的哪一天、為什麼那天平潮只剩二十分鐘、為什麼纜線會在那裡；
     序章到第二章各埋一個線索，在本版結尾（第二章後）用一句話或一張卡指向「三個月後的那一天」。
   - **世界細節**：YX 公司的規模與財務壓力、小艇名字、港口與養殖場的虛構地名（不得用真實公司或品牌）、
     作業的季節與天候、行話（照 `docs/reference/real-rov-research.md`，不要編造不存在的程序）。
   - **禁忌清單**沿用；新增：不寫英雄主義、不誇大危險、不讓 ROV 做真機做不到的事。
2. `docs/story/chapters/`：序章、第一章、第二章各一份**逐關劇本**：每關的開場鏡頭描述、地點字卡、
   每個節拍的無線電台詞（角色、觸發時機、閒置提醒、逾時台詞、成功與低分收尾台詞）、轉折事件與它靠的真實物理。
   對齊 `docs/story/mission-map.md` 的關卡與 R0 的「開場標準」。
3. `docs/story/lines.csv`：補上新台詞（沿用既有欄位；新 key 不得與既有 key 衝突）。附英文、簡中、日文翻譯欄，
   照現有欄位格式；語氣照 bible §4–§5（短、先報狀態再給指示）。
4. `docs/story/between-missions.md`：任務之間的小片段（小艇上的對話、工作日誌、客戶簡訊），每段 ≤ 30 秒可讀完，
   用來讓角色有人味；標明出現時機。只寫文件，實作另案。

## 驗證

- `python simulator/tools/i18n_extract.py --check --integrated` 照過（若 lines.csv 有被檢查）。
- 自我檢查表放 PR 描述：每關是否有角色需求、轉折、收尾；每個角色在每章是否都有台詞。

## 不要做
