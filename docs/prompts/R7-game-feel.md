# R7：手感與回饋（Codex）

> 先完整讀 `docs/prompts/R0-common.md`。分支 `task/R7-game-feel`。

## 背景

擁有者：「遊戲體驗不夠好。」開場之所以有感覺，一半是回饋：張力讀數、無線電喊話、快門閃光。
其他時候飛起來太安靜、撞到東西沒感覺、做對了也沒反應。這個任務只動**回饋**，不動物理與控制語意。

## 先量現況

用 `simulator/tools/browser_*` 的腳本駕駛（或寫一支新的），在開放水域、港口、網箱各錄一段 60 秒操作，
記錄：每個玩家輸入到畫面或聲音有回應的時間、撞擊或纜線受力時玩家得到哪些回饋、整段有幾秒「什麼都沒發生」。
寫在 `docs/design/game-feel-r7/README.md` 的「現況」一節。

## 要做的事（每一項都要能在設定中關掉；超出真機的註冊擬真項目，`real` 預設關）

1. **聲音**（`audio/engine.js`、`audio/mapping.js`）：推進器聲隨各推進器推力與轉速變化、方向感（左右聲道）；
   水下環境底噪隨深度變化；撞擊聲依速度與材質（鋼、混凝土、網、沙）分級；纜線受力時的拉扯聲；
   燈、相機、解鎖的機械聲。真機的操作員在控制台聽得到的只有影像鏈路的聲音（若有）與控制台提示音，
   所以「水下臨場音」要註冊為超出真機的項目（`real` 關），控制台提示音屬於真實。
2. **手把震動**（`input/haptics.js`，PS5 DualSense 優先）：撞擊、纜線張力超過門檻、失聯保護上鎖、拍照成功。
   若 PR #107（P7 設定）已合併，用它的震動強度設定；未合併就自己加，並在 PR 描述說明。
3. **畫面回饋**（只在呈現層）：撞擊時機載影像的短暫晃動與壓縮雜訊（真實影像鏈路會有，屬真實）；
   拍照的快門與閃光（沿用 `hud/photo_feedback.js`）；張力讀數照開場的作法淡入、超過門檻轉色。
4. **無線電反應**：撞擊、纜線繞樁、張力高、電量低、離目標很近時，由角色用一句話反應（bible §5 的語氣），
   有冷卻時間、不重複囉嗦；寫成純函式 `story/crew_reactions.js` 並有 node 測試。
5. **空白時間**：任務中超過 45 秒沒有新事件時，角色給一個與任務相關的提示或閒聊（R4 的 `between-missions.md` 若已合併就用）。

## 驗證

- node 測試涵蓋反應冷卻、門檻、關閉後完全不觸發。
- 瀏覽器：`browser_smoke browser_playstation_smoke browser_cold_open_smoke`，加一支新的 `browser_feel_smoke.py`
  （撞一下、拉一下纜，檢查聲音節點、震動呼叫、無線電台詞都有出現；關掉設定後都不出現）。
- `docs/design/game-feel-r7/README.md` 補「之後」一節，用同樣的量法比較前後。
