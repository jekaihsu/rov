# L1 四種語言的翻譯機制

把下面整段貼給執行的代理。

```
你在 jekaihsu/rov 這個專案（遊戲「ROV Solution」）工作。先完整讀 AGENTS.md（繁體中文，規則有約束力；特別是硬性規則 3、4、7：app.js 是衝突熱點、程式風格、使用者字串集中在各模組頂部的 STRINGS 物件），以及 docs/design/game-plan.md §11（第一版要支援繁體中文、英文、簡體中文、日文）。

背景：
- 目前所有玩家看得到的文字都是繁體中文，放在各模組頂部的 STRINGS 物件裡；伺服器端也有少量玩家文字（qysim 內的 STRINGS、simulator/campaign/*.json 的劇情）。
- 另有多個代理同時在改選單、職涯、品牌等模組，所以這個任務對既有模組的改動必須極小。

任務：基底 main，分支 task/L1-i18n，開 draft PR，標題「L1: 多語機制」。

1. 機制（simulator/viewer/i18n/）：
   - 提供 localize(namespace, STRINGS)：回傳一個物件，讀取時依目前語言回傳翻譯；找不到翻譯就回傳原本的繁體中文。
   - 既有模組只需要把 const STRINGS = {...} 改成 const STRINGS = localize('模組名', {...})，一個模組一行，不要改其他地方。
   - 支援巢狀物件、陣列、帶參數的字串（沿用模組現有的取代方式）。
   - 語言來源的優先順序：網址 ?lang=，其次是設定中的語言（顯示分頁已有語言選單，目前只有繁中），再來是 Steam／瀏覽器語言，最後是繁體中文。
   - 切換語言後不需要重新載入：提供訂閱機制；做不到即時更新的畫面，提示玩家回主選單後生效。
   - 伺服器端文字：先盤點清單，提出做法（由前端依 key 翻譯，或伺服器依連線語言回傳），做法要保持協定相容，寫進 PROTOCOL.md。
2. 翻譯檔：simulator/viewer/i18n/locales/<語言>/<namespace>.json。寫一個工具 simulator/tools/i18n_extract.py，功能：
   - 掃描所有 STRINGS，產生或更新繁中的基準檔。
   - 列出各語言缺少的 key 與多餘的 key。
   - 產生給翻譯者用的 CSV。
3. 先接入的範圍：
   - i18n 機制本身、顯示分頁的語言選單改為四種語言。
   - 選單（simulator/viewer/menu/）、結算（simulator/viewer/play/）、飛行 HUD 的玩家字串。
   - 其他模組列成清單，寫在 PR「後續」。
4. 翻譯內容：
   - 英文、簡體中文、日文各翻譯上述範圍的全部字串。
   - 術語要一致：先寫 docs/i18n/glossary.md，列出 ROV、臍帶纜、定深、DVL 失鎖、牺牲陽極等術語的四語對照，以真實業界用語為準，附來源。
   - 簡體中文不是把繁體逐字轉換，要用大陸慣用語（例如 手把→手柄、解析度→分辨率）。
   - 型號與專有名稱不翻譯：ROV Solution、YX、YX Model R／O／V／S、Block。
5. 版面：英文和日文字串長度不同，檢查選單、結算、HUD 在 1280×720 與 1600×900 沒有溢出或重疊，附四種語言的截圖。
6. 字型：日文與簡體中文需要對應字型，使用系統字型堆疊，不新增字型檔；若一定要加，先在 PR 說明授權與大小。

驗收：
- node 單元測試：
  - 找不到翻譯時退回繁中。
  - 每個語言檔的 key 與基準一致。
  - 帶參數字串在四種語言都保留所有參數。
- cd simulator && python -m unittest discover -s tests 全過；node --test simulator/tests/*.mjs 全過。
- python tools/run_browser_checks.py browser_menu_smoke browser_menu_gamepad_smoke browser_hud_smoke browser_overlay_smoke browser_results_smoke 通過（預設語言下）；另加一個瀏覽器檢查，以 ?lang=en、ja、zh-Hans 各走一次標題到簡報。
```
