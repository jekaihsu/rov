# H1 測試穩定性

把下面整段貼給執行的代理。

```
你在 jekaihsu/rov 這個 ROV 模擬器專案工作。先完整讀 AGENTS.md（繁體中文，規則有約束力），尤其「硬性規則 2：不得為了過 CI 跳過、刪除或放寬既有測試」，以及「本機執行」段落中的 tools/check_matrix.py、run_checks.py 用法。

背景：以下測試在高負載機器上會不穩定失敗，每次審查都要人工判斷「是負載還是真的壞了」，已經嚴重拖慢合併：
1. tests/test_sdk_mock.py MockSDKTest.test_camera_stream：斷言 fps > 5，負載高時只有 1.6–4.7。
2. tools/browser_smoke.py：等待機械臂夾爪 `window.__viewer.S.operations.arm.grip<.5` 逾時；另一次在 `S.rc.right_switch===2` 逾時。模擬跑得比真實時間慢時就會失敗。
3. tools/browser_gameplay_smoke.py：訪客頁面處理 host_only 拒絕訊息延遲到逾時之後；另一次在等待 `mission.last_photo` 時逾時。CPU 剖析顯示主執行緒卡在等待軟體 GPU。
4. tools/browser_expedition_smoke.py：同樣是訪客 host_only 延遲。
5. tests/test_multiplayer.py 的 test_controller_metadata_is_not_cached_with_fleet：依賴 1/30 s 快取時間。
6. tools/browser_paint_smoke.py 第 95 行：工程抽屜開著時遮住 #flightDrawer。main 上也失敗，是真的 UI bug，不是負載。
7. tools/browser_campaign_smoke.py：需要 Playwright 的 ffmpeg，環境沒有就整支失敗。

任務：基底 main，分支 task/H1-flaky-tests，開 draft PR，標題「H1: 測試穩定性」。

原則：讓測試量測「正確的東西」，而不是放寬門檻。
- 能用模擬時間就不要用牆鐘時間。以模擬時間、狀態或事件等待，取代固定 sleep 與牆鐘逾時。
- fps 類測試：
  - 改為驗證串流機制本身正確，例如以模擬時鐘驅動、計算每幀產生成本。
  - 真的需要牆鐘 fps 下限時，可以在偵測到高負載時 skip，但 skip 訊息要寫明原因，而且必須另外保留一個不受負載影響的正確性測試，覆蓋不能減少。
  - PR 描述要逐條說明為什麼這不算放寬。
- 第 3、4 項：
  - 先查清楚訪客頁為什麼處理訊息落後，例如是不是每則 state 都觸發重工。
  - 若是產品 bug（WebSocket 訊息處理被渲染阻塞），就修產品：讓訊息處理不被渲染迴圈餓死。
  - 不能只改測試。
- 第 6 項：修 UI 疊層，並在測試中驗證。
- 第 7 項：沒有 ffmpeg 時跳過錄影步驟，其他步驟照跑，並明確印出原因。

驗收：
- 用 `for i in 1 2 3 4; do python -c "while True: pass" & done` 製造負載。
- 在負載下與無負載下各連跑 5 次：
  - `cd simulator && python -m unittest discover -s tests`
  - `python tools/run_browser_checks.py browser_smoke browser_gameplay_smoke browser_expedition_smoke browser_paint_smoke`
- 跑完記得 kill 背景程序。
- PR 描述貼上兩組 5 次的結果表。目標：全部穩定通過。
```
