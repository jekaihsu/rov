要建的內容（對照照片）：
1. 水面以上：
   - 山谷中的水庫，綠色的靜水，周圍是樹林覆蓋的山坡；遠處一座公路橋。
   - 壩面或護岸：六角形或魚鱗形的混凝土護坡塊，一道階梯通往水邊。
   - 立在護坡上的水位標尺：紅白或黑白刻度，不寫真實數字以外的文字。
   - 浮動碼頭：橘色與藍色的塑膠浮筒拼成兩條棧道，白色欄杆柱與繩索。
   - 碼頭邊停著小型作業船與一艘有遮陽棚的平台船。
   - 碼頭上的 ROV 作業擺設：控制箱、捲成一堆的螢光黃綠色臍帶纜、工具箱。
   - 不放人物，或沿用專案既有的甲板人員模型。
2. 水下：
   - 綠色、低能見度的淡水（2–4 m）；水質類型要新增或選用合適的淡水綠水設定。
   - 傾斜的護坡延伸到水下，淤泥底，沉木與樹枝（臍帶纜的勾纏點）。
   - 進水口結構：混凝土進水塔或進水口、攔污柵（柵條間卡著樹枝與垃圾）、閘門槽。

技術要求：
- 新增情境 key reservoir_intake（參考 qysim/scenarios.py 既有寫法）：淡水、無潮流或極弱流、能見度 3 m、海床類型 mud 或 fluff。
- 起點在浮動碼頭邊。
- 任務目標先放三個：沿護坡下潛到進水口、檢查攔污柵並拍下堵塞處、回到碼頭。
- 攔污柵附近有吸入流的危險，先用一個選填的區域流場參數表示。這屬於物理環境設定，要寫測試，並寫進 PROTOCOL.md。
- 碰撞沿用 world.py 既有形狀；沉木與柵條是勾纏特徵。
- 預算：
  - 水上場景 ≤ 200k 三角形（樹林用少量實例或看板）。
  - 水下 ≤ 150k。
  - 貼圖預設層 GPU 記憶體 ≤ 48 MiB。
  - meshopt＋WebP，並提供低畫質版本。
- 可重現：cad/build_reservoir.py；不提交大型 .blend；授權寫進 CREDITS.md。
- 提供選單用的具名相機錨點：
  - 從護坡上俯看碼頭與水庫（對照照片構圖）。
  - 碼頭上看著設備。

分支 task/M2-reservoir，開 draft PR，標題「M2: 水庫場景」。

驗收：
- 同 M1 的測試與瀏覽器檢查。
- 附模擬器內截圖：
  - 水面上的兩個角度。
  - 水下真實模式機載視角，開燈與關燈。
  - 攔污柵特寫。
- 附資產報告。

共同的畫面標準（擁有者 2026-11-15 的決定，務必遵守）：
- 目標是「像真實照片一樣」：擁有者提供的現場照片就是標準。場景要有真實世界的髒污、鏽蝕、磨損、不整齊與比例感，不要乾淨的低面數幾何。
- 遊戲的選單會把這個場景全螢幕當背景，上面只壓一個大標題與一顆按鈕，所以場景本身要經得起全螢幕、靜止地看。
- 參考照片只能對照，絕不能進入專案（不提交、不裁切、不做投影貼圖）。遊戲中的畫面一律由遊戲自己算出來。
- 做完要自己用模擬器截圖檢查：和參考照片並排看，差在哪裡就繼續改，直到一眼看過去像同一個地方。
