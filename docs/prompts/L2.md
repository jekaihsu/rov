# L2 故事聖經與前三章台詞

把下面整段貼給執行的代理。

```
你在 jekaihsu/rov 這個專案（遊戲「ROV Solution」）擔任編劇。這個任務只寫文件與資料，不改程式。

先完整讀：
- docs/design/game-plan.md（全部；特別是 §9–§11 的決定）
- research_notes/遊戲設計/real_rov_jobs_missions.md（真實工作內容、術語、28 關任務表；第一版只做序章與第一、二章）
- research_notes/遊戲設計/sim_game_patterns.md
- 既有劇情資料 simulator/campaign/*.json 與其格式

已定的方向：
- 玩家是 YX 公司的新進 ROV 駕駛員。
- 調性是寫實職場帶一點輕鬆：無線電有人味、有職場幽默，不搞笑、不奇幻。
- 只用真實會發生的事：纏纜、失聯、趕工、客戶刁難、設備故障、天候窗口。
- 平常的故事藏在簡報、無線電、結算評語裡；每章有一個有演出的大事件。
- 無線電會用 AI 語音合成配音，所以台詞要短、口語、像真的對講機通話。
- 參考的感覺是《潛水員戴夫》的船上生活感：同事有個性，每次回船上都有一點新東西。
- 一關 15–25 分鐘。
- 目標玩家是硬核擬真玩家。

產出（放在 docs/story/）：
1. bible.md，內容包括：
   - 世界與公司：YX 是什麼樣的公司、規模、船、據點，虛構且不影射真實公司。
   - 角色：四到六位，包括主管、纜線手、甲板手、資深駕駛員、客戶代表等。每位寫出背景、說話方式、口頭禪、和玩家的關係、角色弧線。名字要在繁中、英文、簡中、日文四種語言都自然。
   - 配音指示：每位角色的聲音年齡、語速、情緒基調。
   - 無線電通話規範：呼號、確認用語、真實的簡短通話習慣。
   - 禁忌清單：不出現真實公司、真實事故的受害者；遺體改用證物或訓練假人。
2. chapters/prologue.md、chapter1.md、chapter2.md。每章包括：
   - 章節主題與情緒曲線。
   - 每一關的簡報文字（工作單口吻：客戶、地點、工作內容、海況、注意事項）。
   - 下潛中的無線電台詞，依觸發時機列表：開始、接近目標、完成每個目標、常見失誤（撞到、纜線過緊、揚沙）、突發狀況、結束。
   - 結算評語：依金牌、銀牌、銅牌、中止各一段。
   - 本章大事件的完整演出腳本：鏡頭、台詞、配樂情境、玩家要做什麼。
     - 第一章建議是交班前發現異常的趕工檢查。
     - 第二章建議是網箱破洞導致逃魚的緊急處理。
     - 可以提出更好的方案，並說明理由。
   - 每句台詞一行，標明角色，長度不超過 25 個中文字。
3. lines.csv：所有台詞的總表，欄位為 id、章節、關卡、觸發時機、角色、繁中文字、給配音的情緒指示。之後會用來產生配音與翻譯。
4. 任務對應：每一關對應到 research_notes 任務表的哪一項、用哪個既有情境（tutorial_pool、harbor_inspection、hull_inspection、sonar_search、aquaculture_pen）。不發明模擬器做不到的玩法；需要新功能的地方要標明。

分支 task/L2-story，開 draft PR，標題「L2: 故事聖經與前三章台詞」。在 PR 描述說明你的設計取捨，以及需要擁有者決定的地方，例如角色名字、大事件的選擇。
```
