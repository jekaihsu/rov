- docs/design/underwater-visuals/README.md 與 simulator/viewer/fx/README.md（水下光學與水質模型；材質會被 underwater_lighting.js 修補）
- PR #70 的內容，以及審查意見（如下）

審查結果：
- 網格、LOD（268k／89k／18k 三角形）、meshopt＋WebP、距離場與碰撞格式都合格，保留。
- 材質退步：
  - 船殼原本柔和的綠色附著，變成飽和的橘色與薄荷綠迷彩，有明顯像素塊。
  - 碎石發出螢光綠。
  - 工作室畫面的海床失去沙紋，變成平的褐色。
- PR 的截圖在 3.5 m 外拍，水霧蓋住了材質問題。

要做的事：
1. 鏽蝕降低飽和度：深褐、暗赭，不要亮橘。
2. 附著生物改為柔和、低飽和的綠灰與褐灰，依深度分層。
3. 提高船殼的貼圖密度，消除像素塊。可用重複貼圖＋細節貼圖，或圖集重新分配 UV。貼圖預設層仍要 ≤32 MiB。
4. 碎石改用中性的岩石色，不要螢光。
5. 恢復海床沙紋貼圖，或改用場景既有的 seabed.js 海床，不要用自帶的平面。
6. LOD0 是 7.09 MB，超過 2 MB 規則。要嘛壓到 2 MB 以下，要嘛在 PR 描述寫明理由。

驗收：
- 在模擬器內真實模式拍截圖：
  - 機載視角距船殼 1 m 與 3 m，燈光 2 檔
  - 關燈各一張
  - 與舊模型同機位前後比較
- 用 python tools/run_browser_checks.py browser_smoke observation_smoke browser_tether_smoke browser_gpu_bench 檢查。
- cd simulator && python -m unittest discover -s tests 全過；node --test simulator/tests/*.mjs 全過。

直接推到原分支 task/I4-korean-castle，更新 PR #70 的描述。

共同的畫面標準（擁有者 2026-11-15 的決定，務必遵守）：
- 目標是「像真實照片一樣」：擁有者提供的現場照片就是標準。場景要有真實世界的髒污、鏽蝕、磨損、不整齊與比例感，不要乾淨的低面數幾何。
- 遊戲的選單會把這個場景全螢幕當背景，上面只壓一個大標題與一顆按鈕，所以場景本身要經得起全螢幕、靜止地看。
- 參考照片只能對照，絕不能進入專案（不提交、不裁切、不做投影貼圖）。遊戲中的畫面一律由遊戲自己算出來。
- 做完要自己用模擬器截圖檢查：和參考照片並排看，差在哪裡就繼續改，直到一眼看過去像同一個地方。
