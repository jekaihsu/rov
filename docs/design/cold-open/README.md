# 開場（Cold Open）設計筆記

擁有者看過第一次下水的畫面（空蕩的青綠色水、滿版 HUD、兩張清單、無線電字幕、「解鎖推進器 △」）後說：
「我一進來看到這個無聊的畫面我就不想玩了，最一開始讓大家玩很好玩的事非常有必要。」決定採用**倒敘開場**：
新遊戲直接把玩家丟進最漂亮、最緊張的一刻，玩兩三分鐘，出一次真實的事故，然後切到「三個月前」接序章。

依據：`docs/design/game-plan.md` §6（前 10 分鐘）、§11（寫實事故、每章一個有演出的大事件、紀錄片感、乾淨 HUD）；
`docs/story/bible.md`（林岑、周楷、馬力的語氣與呼號）；`simulator/qysim/tether_snag.py`（勾纏的真實處置：
不要硬拉，照原路退出）。

## 1. 原則

- **物理與操控是真的**。場景是一般情境資料（`qysim/cold_open.py`），沿用既有導管架、陽極、纜線與勾纏模型；
  沒有改任何載具、纜線或 SDK 的行為。勾纏是玩家自己的纜線真的卡在 C 腿陽極座上，退回去才會脫開。
  事故靠的是「纜線躺在哪裡」（纜盤位置、放纜長度、平潮流向，見 §5），不是運氣。
- **演出只在呈現層**（`viewer/story/cold_open.js`）：黑畫面、淡入、開場鏡頭、HUD 逐步出現、無線電、配樂、標題卡。
  節奏由 `viewer/story/cold_open_model.js` 依遙測決定（純函式，有單元測試）。
- **不卡關**：玩家不動時無線電會提醒；沒卡到纜、或卡住退不出來，劇情一樣往下走（這是預告，失敗也行）。
- **只播一次**：看過後不再自動播放；設定可關；劇情選單有「重玩開場」。重玩時可跳過（Esc／按住 ○）。

## 2. 分鏡（實作版本）

| 段落 | 時間 | 畫面與聲音 | 玩家 |
|---|---|---|---|
| 黑畫面 | 0–5 s | 全黑、上下黑邊；林岑：「R-1，這裡是指揮。平潮還剩二十分鐘。」配樂淡入 | 無 |
| 開場鏡頭 | 5–13 s | 從黑淡入；鏡頭從 ROV 側面繞到它肩後：亮著燈的 ROV、C 腿與陽極、斜撐、魚群同框；左下角地點字卡「離岸風場 · 導管架 C 腿／水深 12 m · 平潮」；周楷：「纜放好了，線還夠。慢慢飛。」 | 無 |
| 接手 | 13–15 s | 黑邊收起，接回機載攝影機；只出現深度與航向；林岑：「先拍 C 腿陽極，就在你正前方。」 | 推進器已解鎖、定深、燈全開（作業進行中） |
| 靠近陽極 | ～30 s | 單一提示「前進」（玩家自己的按鍵或手把圖示）；3 m 內（或 22 s 後）換成「拍照」並出現準心；18 s 沒動林岑提醒、48 s 馬力提醒、110 s 仍沒拍就往下走 | 飛、拍照 |
| 回報 | 6 s | 快門與閃光、「照片已記錄 · C 腿陽極」；馬力：「乾淨。陽極消耗看得很清楚。」（太遠時：「拍到了。下次再靠近一點。」） | |
| 轉往 B 腿 | 5–15 s | 林岑：「好。沿西面往北去 B 腿，保持深度。」提示「轉向／前進」；20 s 沒動再提醒；85 s 都沒卡纜就以「先到這裡」收尾。纜線繞過 C 腿西南角壓上陽極，往北 3–7 m 內就勾住（腳本駕駛轉向加前進約 4–7 s） | 轉向北、沿西面往北飛 |
| 事故 | 15–40 s | 纜線勾上 C 腿陽極（伺服器勾纏模型的勾點 `tether.snags`，持續 0.6 s 才算；纜線只是碰到鋼構不算）：張力讀數淡入，超過 40 N 轉橘；周楷報實際張力「張力 200！卡住了！」；林岑：「先停！退路想好了嗎？」玩家停手（或 6 s 後）：「別拉。照原路退，往南，退過陽極。」提示由「放開推桿」換成「後退」；再硬拉時周楷喊「別硬拉」；停手不會自己鬆開，退回陽極旁（約 6–10 s）才鬆；100 s 仍解不開就「停住，等平潮再解」收尾 | 放開推桿、後退 |
| 鬆了 | 6.5 s | 勾纏脫開 1.5 s 才算；周楷：「……鬆了。線是自由的。」林岑：「很好。記住這個感覺。」再 2 s 淡出。若勾點在林岑喊退之前自己滑開（少見），改說「……自己滑開了。線鬆了。」「這次是運氣。下次先想好退路。記住這個感覺。」，劇情照常往下走 | |
| 標題卡 | 4.8 s | 黑畫面 → 章節標題卡「三個月前」（序章 / 00、水池照片），配 Morning → 同一分頁載入序章 | |

總長約 1.5–3 分鐘（腳本駕駛不停頓飛完：開場 15 s、靠近與拍照約 10–15 s、回報 6 s、往北 4–7 s 卡纜、事故約 17–20 s、
鬆了到標題卡 8.5 s，共約 65–75 s）。全部無線電都是甲板對講（呼號、短句、先報狀態再給指示），文字走 i18n（繁中、英、簡中、日）；
語音沿用 `audio/voice.js`，目前沒有配音檔，退回無線電雜訊加字幕。

## 3. 與擬真設定的關係

| 項目 | 處理 |
|---|---|
| 物理、操控、纜線、勾纏 | 真實模式，未改 |
| 開場電影鏡頭（第三人稱） | 與下水動畫相同性質的過場（8 s，玩家尚未接手）。接手後一律機載第一人稱（第三人稱仍由 `thirdPerson` 決定） |
| 配樂 | 只在黑畫面、開場鏡頭與標題卡（過場）播放（`audio/music.js` 既有的過場曲目 `cinematic`／`flashback`，不受 `diveMusic` 限制，沒有新增音檔）；接手後交還既有的 `diveMusic` 規則（`real` 關）。同一首曲子同一個 id，`diveMusic` 開著時直接接續不重播 |
| 水下光束／焦散／暗角 | **擁有者核准的過場例外**：只在玩家還沒接手的腳本段落（黑畫面、開場鏡頭）強制開啟，接手那一刻起回到玩家自己的 `waterBeautify` 設定（`real` 關）。見下方說明 |
| 退路指引 | 只用無線電（真實作業中纜手與督導就是這樣喊的），不加箭頭，因此不需要新擬真項目 |
| 開場起始狀態（已解鎖、定深、燈全開） | 「作業進行中」的狀態設定，不是額外能力；照伺服器的解鎖閂鎖規則送出（先送上鎖再送解鎖），玩家隨時可以自己改 |
| 開場時模擬不暫停 | 魚群與纜線在過場中繼續動；機體定深懸停，只隨 0.15 kn 平潮往北北西微漂（15 s 約 1 m）。伺服器照實際時間走，所以開場自己的時鐘每一格最多補 1 s 實際時間（原本 0.25 s）：畫面掉到每秒 1–4 格的機器上，開場仍是 15 s，機體不會在過場裡漂走好幾公尺 |
| 纜線碰觸提示（鋼構變紅、纏繞環、纜線上的紅點） | 開場中不顯示：畫面只有機載鏡頭，纜線在哪裡只靠無線電說（`app.js` 傳入 `plain`、`wrapG`、`contactMesh`）。一般潛航不變 |

**過場例外（擁有者已核准）**：開場的腳本段落是過場，不是飛行，所以畫面可以用既有的水下美化（光束、焦散、暗角）與
過場配樂，即使擬真設定是 `real`。範圍與做法：

- 只在玩家沒有控制權的段落：黑畫面與開場鏡頭（`cold_open_presentation.js` 的 `isScriptedBeat`）。交接、靠近、拍照、
  事故、鬆了這些玩家在飛的段落一律是玩家自己的設定；結束或跳過時也立刻放掉。
- 做成單一、有範圍的覆寫（`viewer/story/cold_open_presentation.js`），只有畫面的唯一讀取點 `fx/beautify.js` 的
  `beautifyEnabled()` 會看它。**不寫入擬真設定**：不呼叫 `fidelity.set`、不改預設組、不碰 localStorage、訂閱者不會收到
  變更通知，也沒有註冊新的擬真項目（因此不存在「`real` 預設為開」的項目）。「還原」就是放掉覆寫，設定本來就沒動過。
- 光束只在有水下後處理的畫質（medium 以上）看得到；performance 畫質沒有這條渲染路徑，過場與飛行看起來一樣，
  所以最低規格的成本不變。
- 驗證：`tests/test_cold_open_presentation.mjs`（覆寫期間與之後，擬真設定快照、儲存內容、寫入次數、訂閱通知都與之前
  相同；哪些段落算腳本段落）；`browser_cold_open_smoke.py` 在黑畫面確認覆寫生效，在玩家接手後確認覆寫已放掉、擬真
  設定快照與 localStorage 和開場前完全相同、畫面美化為關。
- 截圖：`establish-light-shafts-medium-1600x900.jpg`（medium 畫質的開場鏡頭，左側與中間看得到光束）。
- 未做：medium 以上畫質在這 13 s 過場多出美化的成本，§6 的計數是沒有美化時量的，還沒有重量（`waterBeautify` 開著的
  一般潛航本來就有同樣的成本）。

## 4. 何時播放

- **新遊戲**：第一次啟動（標題按「開始」時，沒有任何下水紀錄、職涯進度或完成章節）→ 直接進開場，結束後接序章
  （職涯委託「新人內訓：水池操作課」，即序章章節；沒有職涯資料時改走劇情序章）。
- **劇情或職涯開始**：第一次啟動序章（劇情選單的序章或職涯的序章委託）而開場還沒看過 → 先播開場，再接原本選的序章。
- 看過一次就記在 `rov.coldOpen.v1`；設定的「介面」分頁可以關閉；劇情選單最後一張卡「重玩開場」隨時可以再看
  （可跳過，結束後回到劇情選單）。
- 開場是獨立的戰役條目 `simulator/campaign/cold_open.json`（新分類 `prelude`，不會被自動當成下一章，也不列在
  自由潛航的海域裡），只在新遊戲的啟動流程掛勾；序章本身（可能被 PR #101 改寫）沒有被修改。原本會啟動序章的網址
  放在開場網址的 `next` 參數裡，結束時原封不動地打開。
- 瀏覽器檢查一律以「已看過開場」的設定檔開始（`simulator/tools/_browser.py`），既有檢查的標題與序章流程不變；
  只有 `browser_cold_open_smoke.py` 用全新設定檔。

## 5. 場景（`qysim/cold_open.py`）

- 四腳導管架（與 `jacket_inspection` 同一個產生器），水深 32 m，作業深度 12 m；平潮、0.15 kn、流向北北西（345°）；
  能見度 22 m，水色 `oceanic`（晴天平潮的挑選時刻；暫定值，不是實測）。
- C 腿在導管架西南角。**事故是用纜線的走向設計出來的**（全部是情境資料，暫定值，沒有改物理）：
  - 工作船（纜盤）在東南方 `(-26, 20)`，放纜 45 m，比到機體的直線距離多約 10 m；
  - 平潮的流把這段餘纜推向導管架南面外側，纜線從東邊、貼著 C 腿南側、略低於機體的深度接到機體（開場畫面右下看得到
    自己的纜線往 C 腿右側延伸）；
  - 機體離開陽極沿西面往北，纜線就繞過 C 腿西南角、橫壓在陽極上（彎折約 60–100°），往北 3–7 m 內勾住；
  - 勾纏模型只在這個彎折消失時才放開，也就是機體退回陽極旁邊（照原路往南）；停手時同一股流把機體往勾住的那一側帶，
    不會自己鬆。
- 只有 C 腿 12 m 陽極與它的兩條綁帶可勾纏（150–260 N，與既有 `SnagFeature` 預設同級，暫定）。先前連兩根斜撐也標成
  可勾纏，現在不需要，已拿掉。
- 魚群由情境指定在各腿周圍（導管架是人工魚礁），不用生物群系的隨機位置（`ecology.create_habitat` 新增選填參數，
  其他場景不受影響）。

**為什麼改**。原本的設定（纜盤 `(-28, 12)`、放纜 60 m、流向東）有兩個問題，瀏覽器檢查因此時過時不過：

1. 餘纜 30 m 掛成一個深達 21 m 的大纜彎，漂在船的另一側；纜線從哪個方向碰到陽極取決於纜彎當時怎麼躺。勾纏模型用勾點
   兩側 1.5 m 纜線的水平夾角判斷「彎折是否消失」，纜盤側是鬆的，這個夾角就是隨機的：有時勾上 1 s 內自己鬆開，有時
   退回起點也不鬆（以瀏覽器駕駛的飛法重跑舊設定：6 次中 5 次退不出來、1 次 0.5 s 自己鬆）。
2. 開場把 `tether.snagged_on`（纜線碰到的所有障礙物）也當成「卡住」，纜線只是擦過樁腿就宣告事故、離開就宣告鬆了。
   現在只看 `tether.snags`（勾纏模型真正的勾點）；戰役腳本 `campaign/cold_open.json` 的兩個等待條件也改看 `snags`。

**驗證**（`tests/test_cold_open.py`，直接驅動實體搖桿通道）：往北直飛一定勾在 C 腿陽極上、停在離 B 腿很遠的地方；放開
推桿 25 s 不會自己鬆；全推力硬拉 8 s 不鬆也不斷；不轉向照原路退回陽極旁才鬆、鬆開後不再勾上；另外兩個亂數種子以
鍵盤預設推桿幅度（0.6）重複一次。另以瀏覽器駕駛的飛法（轉向北、直線前進、勾住後 0.6 s 停手、停 25 s、原路退）
做過離線批次（不同亂數種子、拍照位置偏移、停留 8–150 s）：推桿 ≤ 0.6（鍵盤預設、手把半推）93 次中 89 次是「勾住、
停手不鬆、退回才鬆」，2 次勾點在停手後 3 s 內自己滑開，2 次沒勾到（都是在陽極旁停了 100 s 才出發），沒有斷纜，
張力峰值最高 545 N。

**仍然脆弱的地方**（如實記錄）：

- **手把推到底（約 2.2 m/s）撞上勾點**：纜線瞬間張力 450–800 N，接頭強度 889 N（既有暫定值），餘裕很小。離線 12 次
  中 10 次是標準結局，1 次勾點自己滑開，1 次退不出來（走「等平潮」結局）；沒有斷纜，但調整期間放纜較短的設定斷過，
  貼著樁腿飛也斷過一次（走「線斷了」結局）。這是既有物理的結果，沒有為了演出去改；無線電一開始就說「慢慢飛」。
  瀏覽器檢查的駕駛以 0.6 推桿幅度飛。
- **深度**：纜線在機體深度附近繞過 C 腿，陽極只有 1.75 m 長。起始深度 11.5 m（定深）沒問題，11.0 與 12.3 m 也試過
  會勾；更淺或更深沒有逐一試，纜線應該會從陽極上方或下方滑過去，走「先到這裡」結局。
- **時間**：流一直在推纜線與機體。拍完 90 s 內出發都會勾；停到 100–150 s 才出發，10 次左右有 2 次沒勾到（走「先到
  這裡」結局），也有機體自己漂過陽極、纜線先勾上，事故在「轉往 B 腿」一開始就發生的。
- **離西面多遠**：貼著西面外 1–2 m 往北（往 B 腿拍照點的直線）纜線繞角最大。瀏覽器檢查有一次飛到西面外 3.3 m，
  勾住後停手 6 s 內勾點自己滑開（走「自己滑開了」那兩句）；檢查的駕駛現在沿 B 腿拍照點正南方那條線分段飛。
  玩家飛得更外面時，比較可能是「自己滑開」而不是「退回才鬆」。
- **近距離的燈**：performance 畫質沒有曝光後處理，燈全開、離樁腿 1.5 m 以內時樁腿上是一塊過曝的亮斑；貼到 0.5 m 以內
  就是舊連續影格裡那個白色大圓盤。這次沒有改燈或曝光，只讓檢查的駕駛停在拍照點（離陽極約 2 m）不再滑到陽極前面，
  過場與交接的畫面沒有這個問題。
- 開場與一般潛航一樣，纜線會出現在機載鏡頭裡（右下往 C 腿右側）。這是纜線真正的位置，沒有另外藏起來；纜線的碰觸
  提示（紅點、紅環、鋼構變紅）在開場中關掉。

## 6. 效能

（字幕、提示、黑邊）和 8 s 的第三人稱過場（與第三人稱視角同成本）。開場起點的計數（`browser_gpu_bench.py
--profile`，1280×720，seed=1 起始姿態即開場起點；`third` 即開場鏡頭的距離），已寫入 `tools/perf_budgets.json`
（量測值加約 15 %）：
