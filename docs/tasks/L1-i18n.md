# L1：多語機制

需求：第一版介面支援繁體中文、英文、簡體中文、日文。基底 main，draft PR。
範圍：viewer/i18n、顯示語言選單、menu／play／hud 的 STRINGS；不改 app.js、物理與 SDK。

- `localize(namespace, STRINGS)` 以 Proxy 保留巢狀物件、陣列與既有 replace 插值方式。
- `core.js` 提供 resolveLanguage、registerTranslations、setLanguage、subscribe（回傳取消訂閱）。
- `index.js` 在 ES module 初始化時載入選定語言，網址 > 已儲存設定 > Steam > 瀏覽器 > 繁中。
- Steam 使用既有 preload `steamStatus().language`。字典失敗退回模組原始文字。
- 設定切換不重新載入，更新現有靜態文字與動態讀值；已組合／快取的文字提示返回主選單後生效。
- 新模組接入只需 import 與包裝 STRINGS（物件結尾 `};` 改為 `});`）。
- 系統字型，不新增字型檔。翻譯檔是可人工維護的來源資料，不是 runtime bundle。

工具：`python simulator/tools/i18n_extract.py --csv /tmp/translations.csv`。
工具掃描前端 STRINGS 與後端以 STRINGS 結尾的字典，更新繁中基準，列出所有缺少／多餘 key。
`--check` 不寫基準；尚未接入的 namespace 會如實報缺少翻譯，不應以繁中填滿外語檔偽裝完成。
目前 JS 來源採 literal STRINGS 格式；唯一支援的計算值是既有 fleet 名稱／用途，其他運算會明確失敗。
CSV 含 namespace、key、四語文字，可供翻譯者編輯；CSV 匯入未列入本次範圍。

驗證：Node 完整測試、Python unittest discover、標準瀏覽器 smoke 以及 browser_i18n_smoke。
四語截圖放 docs/i18n/screenshots，為本任務驗收所需，未修改 docs/showcase。

後續：其餘 STRINGS 模組與伺服器內容見 i18n/locales/zh-Hant 盤點、PROTOCOL.md L1 章節。
目前介面仍可能顯示未接入模組／伺服器繁中內容，不能宣稱整款遊戲已完成四語。

既有瀏覽器測試斷言是繁中，因此 `_browser.py` 將測試 context 的預設 locale 固定為 zh-TW。
可用 `ROV_BROWSER_LOCALE` 或 context 的 `locale` 覆寫；新增測試仍測試英文瀏覽器自動選語言。
這只影響測試環境，不更動遊戲優先順序或放寬既有斷言。
