# T19 後端效能

**目標**：README 自承「四台複雜纜線場景可能慢於即時」。讓 3 人房間在一般筆電上穩定即時，並留出聲納、劇情等新功能的餘裕。

**範圍**：`simulator/qysim/`（以 `tether.py`、`_cable_accel.py`、`world.py`、`room.py`、`server.py` 為主）、`simulator/tools/benchmark_room.py`、`simulator/tests/`。**不得改變物理結果**（見第 3 點）。

**要做**

1. **先量測**：擴充 `benchmark_room.py`，輸出 1／2／3 台載具在各情境下每個物理步的耗時分解（剛體、纜線、碰撞、洋流、任務、序列化、網路）與即時倍率。把基準數據寫進 `docs/physics-performance.md`。
2. **最佳化**（依量測結果決定優先順序）：纜線求解向量化與避免重複配置、碰撞的空間分割與早退、狀態序列化的增量或降頻、不需每步更新的子系統降頻、可選 Numba 路徑的涵蓋範圍。
3. **結果一致性**：建立回歸測試，固定種子跑數個情境 30 秒，最佳化前後的位置、姿態、纜線張力差異必須在明確容差內（位置 1 mm、張力 0.5%）。若某項最佳化會改變數值，在 PR 描述逐項說明。
4. **網路**：狀態封包大小與頻率的量測與精簡，不破壞既有客戶端；用 `tools/profile_network.py` 回報前後數據。
5. **目標**：3 台載具、最重的纜線情境，在 4 核心筆電等級的 CPU 上即時倍率 ≥ 1.5（無 Numba 時 ≥ 1.0）。達不到就如實回報瓶頸。

**驗證**：前後基準數據表；一致性測試與既有測試全過。
