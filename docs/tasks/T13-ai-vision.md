# T13 AI 視覺：機載畫面即時物件偵測

**目標**：機載鏡頭畫面上即時框出目標（魚、珊瑚、陽極塊、纜線、裂縫標記等），像真實遙控器螢幕上跑 AI 辨識。同時讓公司把模擬器當成訓練與驗證視覺模型的資料工廠。

**範圍**：新增 `simulator/viewer/vision/`、`simulator/tools/vision/`、`simulator/sdk_mock` 相機介面的偵測結果擴充（選填）。不改物理。

**授權注意（重要）**：Ultralytics 的 YOLOv5／v8／11 程式與權重為 AGPL-3.0，不可放進商業發行的遊戲。遊戲內建模型僅可使用寬鬆授權的實作與**自行訓練**的權重（例如 Apache-2.0 的 YOLOX、RT-DETR、D-FINE 類）。內部研究可另行使用其他模型，但不得進入發行建置。PR 中列出所用程式碼與權重的授權。

**要做**

1. **真值標註產生器**：利用既有投影與射線邏輯（`observation_camera.js`），對機載畫面中每個可見實體輸出 2D 邊界框、類別、遮蔽比例、距離。這同時是遊戲內的「理想偵測器」（不需模型就能運作）與資料集的標註來源。
2. **合成資料集工具**：`simulator/tools/vision/make_dataset.py` 以無頭瀏覽器沿隨機或錄製的航跡擷取機載畫面，隨機化能見度、深度、燈光、揚沙、洋流、相機雜訊，輸出 YOLO 與 COCO 兩種格式，含訓練／驗證切分與類別統計。附類別定義檔。
3. **偵測器介面**：`vision/detector.js` 定義統一介面 `detect(frame) -> [{cls, score, box}]`，三個實作：
   - `oracle`：用真值，可加入可調的漏檢、誤檢與框抖動，模擬真實模型的不完美。
   - `onnx`：以 onnxruntime-web（MIT）在瀏覽器執行 ONNX 模型，優先 WebGPU，退回 WASM；在 Web Worker 中推論，不卡渲染；輸入解析度與推論頻率可調（預設 10 Hz，框以追蹤插值到每幀）。
   - `remote`：透過 WebSocket 把畫面送到外部推論服務並取回結果，供公司自己的模型與 SI 整合使用。附一個最小的 Python 參考服務。
4. **訓練腳本**：`simulator/tools/vision/train.md` 與腳本，說明如何用步驟 2 的資料訓練一個小模型並匯出 ONNX。若執行環境無 GPU，提供流程與設定，並如實標示「尚未實際訓練出可用權重」；此時遊戲預設使用 `oracle`。
5. **畫面呈現**：機載視角疊加偵測框、類別、信心值，樣式依 `docs/design/ui-direction.md`；可開關；顯示推論延遲與幀率。遙控器螢幕（操作員小畫面）同步顯示。
6. **玩法結合**：偵測到的目標可一鍵標記到小地圖；圖鑑攝影時提示「畫面中有可登錄目標」；巡檢任務可要求「AI 確認目標後拍照」。這些以選項形式加入，不改變既有判定規則。
7. **SDK**：`sdk_mock` 相機新增選填方法取得目前偵測結果，讓既有 Python 程式能讀取。此為模擬器擴充，文件中明確標示非原廠 SDK 介面。
8. **效能**：開啟 `onnx` 偵測時，中階獨顯上幀率下降不超過 15%；整合顯示晶片自動降頻或退回 `oracle`。

**測試**：真值框與實際渲染位置的一致性（已知機位下框中心誤差小於 2 像素）；`oracle` 劣化參數的統計行為；資料集輸出格式驗證。附偵測疊加的錄影。
