# T11 寫實重新建模與資產管線

**目標**：現有模型是低面數示意風格（工作船、甲板人員、海床、結構物）。改為寫實 PBR 風格，並建立之後能持續替換資產的管線。

**範圍**：`cad/`、`simulator/viewer/models/`、`simulator/tools/`（資產建置腳本）、`simulator/viewer/vehicle_models.js`／`glb.js`／`environment.js`／`deploy_intro.js`／`figures.js`（載入與擺放）。碰撞幾何若隨模型改變，同步更新 `simulator/qysim` 的對應資料與測試。

**原則**

- 寫實來自**材質、比例與細節**：PBR 貼圖（基礎色、法線、粗糙度、金屬度、AO）、正確的實際尺寸、倒角與接縫、磨損與海生物附著。不是單純加面數。
- 資產來源僅限：自行以 Blender 腳本建模；CC0 資產庫（例如 Poly Haven、ambientCG、Quaternius）。每個外部資產逐一寫入 `CREDITS.md`（來源網址、作者、授權、修改內容）。不得使用來源不明、需署名以外限制或禁止商用的資產。
- **載具採原創的通用設計**：觀測級小型 ROV、帶機械臂的作業級 ROV、開放框架式 ROV 各一。外形符合真實工程邏輯（推進器配置、浮力材、框架、燈、相機、纜線接頭），但不得複製任何廠商機型的外觀、名稱、標誌或配色。推進器位置須與 `simulator/qysim/vehicles.py` 的物理定義一致。現有三個模型保留為內部訓練版資產，Steam 版使用新模型（以設定切換）。

**要做**

1. **管線**：`simulator/tools/build_assets.py`：Blender 無頭匯出 → glTF → meshopt 壓縮、KTX2／Basis 貼圖壓縮、自動產生 LOD（至少 3 級）與碰撞代理。輸出每個資產的三角形數、貼圖記憶體、檔案大小報表。來源 `.blend`／腳本放 `cad/`，產生的 `.glb` 才進 `viewer/models/`。
2. **預算**：主角載具 ≤ 80k 三角形、2K 貼圖；工作船 ≤ 120k；人物 ≤ 40k；場景道具依距離分級。單一 `.glb` ≤ 8 MB，全部模型合計 ≤ 120 MB。
3. **重做清單（依序）**：
   1. 三台原創載具（含可動件：推進器槳葉、機械臂關節、雲台、燈）。
   2. 工作船與甲板設備（絞車、A 架或吊臂、控制櫃、纜線盤）。
   3. 甲板人員（寫實比例、工作服、救生衣、安全帽；骨架沿用 `humanoid.js` 的 IK 介面）。
   4. 海床與地形材質（沙、礫、泥、岩，依場景混合）；礁岩、珊瑚、海草、海藻。
   5. 人造結構：導管架樁腿與陽極塊、單樁、船殼、碼頭樁、管線、沉船細節。
   6. 魚類（3–5 種體型，骨架或頂點動畫游動）。
4. 每完成一類開一個 PR（T11a、T11b…），不要一個巨大 PR。每個 PR 附轉台截圖、線框圖、資產報表、遊戲內同機位前後對比。
5. `model-preview.html` 擴充為資產檢視器：切換 LOD、線框、貼圖通道、碰撞代理。

**限制說明**：純程式建模能達到「乾淨、可信的工業外觀」。若要達到照片級，需要美術人員或掃描資產；請在 PR 中如實標示哪些資產仍是程式生成的近似。
