# 潮間帶工作隊戰役

主選單選擇「潮間帶工作隊」開始水池練習。工程面板的「章節 / 訓練課程」可重玩已解鎖章節、
略過序章、回看無線電紀錄，或勾選公司課程後開始同一腳本。
Enter 顯示完整台詞，再按一次繼續；飛行與作業倒數不會因對話暫停。

## 章節與作業

每章的三個 `task_*` objective 是作業任務，對話、提示與條件節點不另算任務。
章節依序解鎖；故事中的「折潮」是虛構案件代號，不指涉真實船名。

| 章節 | 場景 / 模式 | 三段作業與判定 | 核心技能 |
| --- | --- | --- | --- |
| hull 船殼 | hull_inspection / inspection_coop | 入口、龍骨、擦碰：依序確認各站三秒穩定拍照 | 濁水減燈、停下辨認、保留返回輪廓 |
| harbor_signoff 交班複查 | harbor_inspection / inspection_coop | 樁面、樁腳、交接：三站穩定拍照 | 面對結構檢查、適量放纜、換面前留退路 |
| offshore 離岸 | jacket_inspection / inspection_coop | 迎流接近、抗流定點、外側換面：面向陽極塊三站拍照 | 推力控制、有效底鎖才依賴定點、不穿斜撐 |
| reef 礁區 | coral_reef / expedition | 一筆有效生態觀察、回收合約、部署合約 | 低干擾攝影、先照後取、放穩再拍 |
| wreck 沉船 | wreck_survey / inspection_coop | 艏、側面、艉三站拍照，逐步提出壓艙座與排水疑點 | 深水外側檢查、抗流、低能見度與防勾纏 |
| finale 夜間回收 | harbor_inspection / expedition | 回收封存匣、部署復查基準、潮窗三站核驗 | 證物交接、三人通聯、資料不足就中止 |

礁區與終章開始前，先在章節面板按「部署解鎖的作業載具」。交班複查完成後此按鈕可用。
沒有機械臂的載具無法接回收或部署合約；開始後若選錯載具，先從操控面板切換作業載具，
再從章節面板重開本章，避免沿用切換前的作業狀態。
工程合約從既有海洋探索與工程面板接案，腳本不會替玩家按下接案。
礁區按回收、部署順序；終章按回收、部署、巡檢順序，勿插入其他合約。
取消未完成合約可重接同類；若已完成錯誤類別，重開章節。

回收必須先拍攝物件原位，再以機械臂夾取、運送到交接點、放開穩定兩秒。
部署必須實際夾取與運送、放穩兩秒，最後取得可辨識的完工照片。
生態照片必須通過既有機載相機幾何、可見度與遮擋驗證；一般 JPG 數量不算生態紀錄。
終章沿用工程物件外觀與「工具箱」標籤，台詞把它定義為封存匣的轉運容器，沒有新增場景資產。

## 結局與中止

終章第三份巡檢合約接案後開始計時，十二分鐘內三站全部核驗得到 `ending_evidence_complete`；
未完成三站便返回深度小於 1.5 m、逾時或斷纜，得到 `ending_open_question`，報告封存待查。
分支依本次潛航的工程結果，**不宣稱讀取前章證據**；既有條件取樣只含載具 viewer state，
沒有 campaign 的獎勵或歷史調查資料。前章線索以無線電銜接，本章重新查證。

四個協作巡檢章節沿用整趟 720 秒倒數。逾時或斷纜會明確中止並停在重開提示，
不發獎勵、不解鎖下一章。請從章節面板重開。成功不要求製造碰撞或刻意繞纜。
碰撞與最大張力仍列入既有章節成績；沒有虛構已完成解纜的成功台詞。

## 節奏與目前邊界

原任務書要求每段 5–15 分鐘。礁區與終章前兩段以 5–15 分鐘作為設計預留，仍待人工試玩量測；
終章核驗窗口為 12 分鐘。四個協作巡檢章節三段共用 12 分鐘，**尚未達到每段 5–15 分鐘**。
要達成需支援章內多潛次／重啟任務計時；本次只改內容，沒有改引擎的 720 秒限制或加入空等。

研究依據見 [真實 ROV 研究](reference/real-rov-research.md) 的「纜線、聲納、流程」與
「檢測怎麼飛、事故怎麼發生」：濁水減少背向散射、適量放纜、勾纏不盲拉、強流下外側作業、
定深不等於水平定點、先留影像再搬動。三秒拍照／兩秒放穩是既有遊戲判定，並非實機驗收標準。
3 m／4 m 能見度、十二分鐘潮窗及工程件作為證物都是內容設計假設，不是機型實測數值。
目前 checkout 沒有 `docs/reference/own/`，未引用不存在的實測資料。

本次未新增的能力：強制且可驗證的離岸解纜、單樁換場、沉船內部與 32 m 海床、沉船場景工程合約、
真正夜間光照、跨章證據完整度。既有沉船場景海床為 30 m，因此台詞明確不要求下到 32 m。
夜間是故事時間，`environment` 只能調能見度；不是以能見度模擬天色。

## 腳本契約與存檔

腳本位於 `simulator/campaign`，`schema.json` 描述格式。每章必填 `category`（story / incident）
與 `order`，章節清單依（category、order）排序。自動啟動只挑 story，事故演練需明確啟動。
條件路徑為載具 state 的點分隔路徑，陣列用數字，例如 `mission.targets.0.completed`、
`expedition.results.0.kind`、`pos.2`。比較只有 eq / gt / lt，不支援跨欄位比較或跨章獎勵查詢。
支援 dialogue、wait、objective、hint、branch、reward、checkpoint、environment、spawn、remove；
environment 目前僅支援 visibility_m。新增台詞、目標與提示集中在各章 `strings.zh-TW`。

輪詢分支前保留 wait，讓執行器能在下一次取樣重新判定，避免同一 tick 無限迴圈。
新章節只在開頭與結尾存檔，不在物件回收或三站巡檢中間存檔：恢復會重置物理世界，
不能把上次的物件／站點結果當成這次仍存在。中止或未完成的章節從頭重做證據鏈。

本機保存章節解鎖、獎勵與成績，不是雲端存檔。序章解鎖下潛貼紙，交班複查解鎖作業載具。
沒有預錄語音；對話沿用裝置 glyph。實際操控仍依全站擬真設定，劇情不改物理或 SDK。

## 自動驗證

```bash
cd simulator
pip install -r requirements.txt
python -m unittest discover -s tests
```

`tests/test_campaign.py` 保留六章自動通關入口，使用 `tests/test_campaign_chapters.py` 的驅動器
自動推進無線電、送拍照／接案／機械臂指令至結束，
另驗證兩種結局、潮窗逾時、巡檢中止、語系引用與任務數。
與既有 mission_modes／expedition 測試相同，轉場位置採確定性 pose fixture；
完成標記、照片資格、合約結果與章節 index 不由測試直接寫入。
**這不是序章那種全程 RC 物理飛行測試，也不能證明人工操作可在目標時長內完成。**
既有序章的 real-input 測試仍隨全套測試執行。
